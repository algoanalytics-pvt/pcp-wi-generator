WI Generator: Model Comparison

Part 289661208202 · CROSSMEMBER LH 2DR XENON CAB · Stage 01 · Source: PPAP 289661208202 updated.xlsx · Evaluated 10 November 2026
Summary
  • No model passes the judge. Every model fails at least one gate: a contradicted critical fact, a critical hallucination, or critical recall below 0.95.
  • Luna-6 scores highest (0.873), with Luna-5.6 close behind (0.853) and the best critical recall (0.931). They are the only models that produce the full press process (shearing, draw, trim & piercing, restrike) with correct settings and dimensions.
  • Luna-6 costs about the same as gpt-4o-mini ($0.0039 per WI) and less than half of Luna-5.6 ($0.0085). The quality gap is not a cost trade-off.
  • gpt-4o-mini and Nano-5 copied the welding example in the generator prompt instead of reading the PPAP. Example values (UNIT-3, 11/11/17) also appear in mistral-small and Luna-5.6. Fixing the prompt example is the top action, ahead of choosing a model.
  • Most of the Luna models' “hallucinations” are real PPAP data that the golden WI leaves out. The judge prompt cannot tell these apart from invented values, which caps the top models' results.

Root causes

1. The prompt's filled-in example leaks into the output

The JSON schema example in pcp_wi_generator/prompt_builder.py (lines 48–104) is a complete welding WI for a different part (COVER ASSY FUEL FILTER). Weaker models copy it instead of extracting data from the PPAP:

Output length does not explain this: gpt-4o-mini and Nano-5 ran with a 4,000-token limit (the others had 16,000), but used only 577 and 745 completion tokens.

2. Header fields are mapped inconsistently

The PPAP has two sets of revision data: the part revision (01 / 22.02.2020, which the golden uses) and the PCP/PFD form revision (00 / 11/11/17). Luna-5.6 took the form revision. Stage No. was filled with operation codes by Luna-6 (“PP-010 to PP-080”) and mistral-small (“PP-030”). None of these errors come from the process content; they come from unclear header rules.

3. The judge penalises detail that the PPAP supports

The judge scores only against the golden WI. Minimum shut heights (795/760/750 mm), D 513, liner and cushion-pin sizes, and the F-PRD-17 / RG-PRD-01 / F-QMS-6 / F-DVP-29 form references are all in the PPAP, but count as critical hallucinations. These make up most of Luna-6's 13 and Luna-5.6's 17. Additions that are actually invented are a small, distinct set: mistral-small's tolerances, Nano-5's welding process and Luna-6's hardness gauge.

4. Golden rework rows cannot be derived from the PPAP

“Plastic mallet”, “rust remover” and “rust preventive” appear nowhere in the PPAP. They match the generator's built-in example, so the rework section (weight 0.15) rewards copying the example more than reading the source. Rework is the weakest section for every model; the best is Luna-6 at 0.50.

Recommendations

  1. Replace the filled-in example in prompt_builder.py with a schema of placeholders, or with a press-shop example, and tell the model never to copy example values. Then re-run all five models. This should stop the copied welding content and the UNIT-3 / 11/11/17 values.
  2. Add explicit header rules to the prompt: use the part revision and revision date (not the form's), set Stage No. to the WI stage number (not operation codes), and give the factory/line area format.
  3. Add a source-supported class to the judge, for example SOURCE_SUPPORTED_ADDITION, for extra content that can be traced to the PPAP. It should not trip the hallucination gate. Keep the gate for content found in neither the golden nor the PPAP.
  4. Review the golden rework rows, or pass the house-standard rework actions into the prompt, so the rework score measures something the model can actually derive.
  5. Use Luna-6 as the lead candidate, with Luna-5.6 as the alternative if critical recall matters more than cost. Make the final choice after re-running with the fixed prompt, on more parts and stages; this report covers a single WI.

Method

Judge. Each generated WI was compared with its golden WI (Hindi/WI_20260616_PPAP 289661208202 updated_Stage_01.xlsx) using wi_judge_single_prompt.md. Claude applied the prompt; eval_tools/score.py computed every score from the verdicts, so the arithmetic is exact and auditable.

Golden facts. Each golden WI was split once into atomic facts, and the same list was used for every model. Each fact is MATCH (1.0), PARTIAL (0.5), MISSING (0) or CONTRADICTED (0), weighted 3 / 2 / 1 for critical / major / minor.

Pass rule. A model fails if any critical fact is contradicted, if there is any critical hallucination, or if critical recall is below 0.95.

Judgement calls applied to all models:

  • Content found anywhere in the generated WI counts, even if it sits in a different section from the golden. For example, a value given only in QC can satisfy a step fact if it applies to the same operation.
  • Document and revision dates count as critical facts, under the prompt's “any numeric value / revision” rule.
  • A check named without its value (“measure stroke length”) or with the wrong instrument (hardness gauge) is PARTIAL.
  • A rework row with the right defect but a different action (reject or re-pierce instead of repair) is CONTRADICTED.
  • Content not in the golden counts as a hallucination even when the PPAP supports it, because the prompt says to judge only against the golden (see root cause 3).

Limits. This covers one part, one stage and one generation per model. Treat the ranking as indicative until it is repeated on more WIs.
