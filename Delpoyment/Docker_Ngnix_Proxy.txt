Browser-test the built PCP -> WI Generator SPA behind a prefix-stripping proxy.

Run every command from the repo root (.../pcp-wi-generator).

Why this is needed: the built SPA's asset URLs are baked with the
/pcp_wi_generator/ prefix (frontend/vite.config.js `base`), so loading
http://localhost:9274/ directly shows a BLANK PAGE — the asset requests 404 into
the catch-all and get index.html back. That is expected, not a bug. To test it
the way production works, put a throwaway nginx in front that strips
/pcp_wi_generator/ and proxies to the container — exactly what the real EC2
nginx does. See DEPLOYMENT.md for the production nginx block.

(The QuoteVault version of this recipe is kept at
reference/quote_vault_Docker_Ngnix_Proxy.txt.)


────────────────────────────────────────────────────────────────────────────
1. Create the .env the container needs
────────────────────────────────────────────────────────────────────────────

docker-compose.yml declares `env_file: .env`, so the file must exist or compose
refuses to start. An empty one is fine for everything except actually generating
Work Instructions (that needs a real LLM provider key).

cp .env.example .env        # then fill in ONE provider key, or leave blank
# quick version if you're only testing routing/assets:  touch .env


────────────────────────────────────────────────────────────────────────────
2. Build and start the app container
────────────────────────────────────────────────────────────────────────────

docker compose up -d --build

# watch it come up (Ctrl-C to stop tailing; the container keeps running)
docker compose logs -f
# expect: "Uvicorn running on http://0.0.0.0:8000"

docker compose ps
# expect: pcp_wi_generator_web ... Up ... 0.0.0.0:9274->8000/tcp

First build takes a few minutes (npm ci + pip install). Rebuilds are cached.


────────────────────────────────────────────────────────────────────────────
3. Sanity-check the container directly on 9274 (no proxy yet)
────────────────────────────────────────────────────────────────────────────

curl -s -w " [%{http_code}]\n" localhost:9274/health
curl -s -w " [%{http_code}]\n" localhost:9274/api/health
curl -s -w " [%{http_code}]\n" localhost:9274/api/training-status
# expect 200 + {"ready":true,...} — proves training_data/ made it into the image

curl -s localhost:9274/ | grep -o '"/pcp_wi_generator/[^"]*"'
# expect the favicon + /pcp_wi_generator/assets/index-*.js and *.css tags

Do NOT browse http://localhost:9274/ yet — blank page, see the note above.


────────────────────────────────────────────────────────────────────────────
4. Write the throwaway nginx config
────────────────────────────────────────────────────────────────────────────

It must live under $HOME — Docker Desktop won't bind-mount from /tmp.

mkdir -p ~/docker_test_scratch
cat > ~/docker_test_scratch/nginx-pcp-wi.conf <<'EOF'
server {
    listen 80;

    # PCP workbooks run 0.5-2.5 MB; nginx's 1m default would 413 the upload.
    client_max_body_size 50m;

    location /pcp_wi_generator/ {
        # trailing slash on proxy_pass = strip the /pcp_wi_generator prefix
        proxy_pass http://pcp_wi_generator_web:8000/;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Prefix /pcp_wi_generator;

        # /api/generate makes one LLM call per selected sheet, serially.
        proxy_read_timeout 600s;
    }
}
EOF


────────────────────────────────────────────────────────────────────────────
5. Find the compose network the app container is on
────────────────────────────────────────────────────────────────────────────

docker network ls | grep -i pcp
# -> pcp-wi-generator_default

Compose derives that from the project directory name (lowercased). If you
renamed the folder, use whatever this prints in step 6.


────────────────────────────────────────────────────────────────────────────
6. Run the throwaway nginx on that network, publishing 9284 -> 80
────────────────────────────────────────────────────────────────────────────

docker run -d --rm --name pcp_wi_nginx_test \
  --network pcp-wi-generator_default \
  -p 9284:80 \
  -v ~/docker_test_scratch/nginx-pcp-wi.conf:/etc/nginx/conf.d/default.conf:ro \
  nginx:alpine

`proxy_pass` targets the container name pcp_wi_generator_web on its INTERNAL
port 8000 (not the published 9274) because nginx is on the same Docker network
here. On the real EC2 host nginx runs outside Docker and targets
127.0.0.1:9274 instead.


────────────────────────────────────────────────────────────────────────────
7. Verify through the proxy (worth it — confirms assets aren't 404ing as HTML)
────────────────────────────────────────────────────────────────────────────

curl -s -o /dev/null -w "index:  %{http_code}\n" http://localhost:9284/pcp_wi_generator/
curl -s -o /dev/null -w "health: %{http_code}\n" http://localhost:9284/pcp_wi_generator/health
curl -s -w " [%{http_code}]\n" http://localhost:9284/pcp_wi_generator/api/training-status

# every asset referenced by the served HTML, with its content-type
for U in $(curl -s http://localhost:9284/pcp_wi_generator/ | grep -oP '(?<=(src|href)=")[^"]+'); do
  printf "  %-52s " "$U"
  curl -s -o /dev/null -w "%{http_code} %{content_type}\n" "http://localhost:9284$U"
done
# expect 200 application/javascript for the .js and 200 text/css for the .css.
# A 200 text/html here means the prefix isn't being stripped — recheck step 4/6.

# optional: a real upload end-to-end through the proxy
curl -s -X POST -F "file=@inputs/215331700141pcp.xlsx" \
  http://localhost:9284/pcp_wi_generator/api/upload-pcp | head -c 300; echo


────────────────────────────────────────────────────────────────────────────
8. Browse it
────────────────────────────────────────────────────────────────────────────

http://localhost:9284/pcp_wi_generator/

Use the trailing slash. Hard-refresh (Ctrl-Shift-R) if you tested an earlier
build — the old blank page caches.

Uploading works; clicking Generate needs a real provider key in .env (otherwise
the API returns "No API key found"). After editing .env:
  docker compose up -d          # recreates the container with the new env


────────────────────────────────────────────────────────────────────────────
9. Tear down
────────────────────────────────────────────────────────────────────────────

docker rm -f pcp_wi_nginx_test     # --rm means stopping it removes it
docker compose down
rm -rf ~/docker_test_scratch       # optional


────────────────────────────────────────────────────────────────────────────
Troubleshooting
────────────────────────────────────────────────────────────────────────────

- Blank page at :9284 but :9274 "works" — you're testing the wrong port. 9274
  is the raw container and is *supposed* to look blank in a browser.

- 502 from the proxy: the app container is down or on a different network.
  `docker compose ps` and re-run step 5.

- Frontend changes not showing: the SPA is baked into the image at build time.
  `docker compose up -d --build` again — plain `up -d` won't rebuild it.

- 413 on upload: client_max_body_size missing from the config in step 4.

- Port 9284 already in use: pick any free port, e.g. -p 9285:80, and use it in
  the URLs above. 9274 is the app's published port — don't reuse it.
